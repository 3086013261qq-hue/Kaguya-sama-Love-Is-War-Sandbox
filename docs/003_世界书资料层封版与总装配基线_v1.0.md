## 2. 本轮冻结范围

### 2.1 世界规则

- `worldbook/core/`：9 条蓝灯，职责冻结。
- `worldbook/green/`：34 条绿灯，职责冻结。
- 蓝灯保持全局底层事实；绿灯保持按场景触发的展开规则。
- 禁止在总装配时将绿灯重新并回蓝灯，禁止因方便触发而扩大蓝灯常驻正文。

### 2.2 人物与替身

- `characters/stand-augmented/`：已完成的角色本体条目。
- `characters/stand-abilities/`：对应替身能力条目。
- 人物本体与能力必须继续拆成独立世界书条目；不得在装配时重新合并。
- 高阶形态与特殊进化条件保持现有锁定，不得由装配器提前解锁。

### 2.3 地点

- `locations/university_locations.md` 为大学世界线正式地点事实源。
- 原高中措辞、旧母卡地点只可作历史资料，不得重新回灌正式运行时正文。

### 2.4 时间线

- `timeline/university-stand/season1_university_stand.md`
- `timeline/university-stand/season2_university_stand.md`
- `timeline/university-stand/season3_university_stand.md`

三季大学替身版时间线为正式时间线输入。时间线正文必须保持完整 `<world_timeline>` 结构，不因装配拆成事件碎片。

### 2.5 原卡保留层

`source/`、`timeline/original/` 与旧 `worldbook/final/` 83 条模块仅保留为母版事实、历史产物与迁移参考，不再作为本轮正式 Character Book 的直接运行时成品。

## 3. 正式装配技术口径

本轮统一采用：

- 咩咩制卡·全栈 v1.0.0
- chara_card_v3
- 内嵌 `character_book`
- ccv3 snake_case 字段
- 不修改咩咩预设本体

### 3.1 字段硬规则

- 禁止 `preventRecursion / excludeRecursion / displayIndex / scanDepth` 等 camelCase 同义字段与 snake_case 并存。
- 使用 `prevent_recursion / exclude_recursion / display_index / scan_depth` 等母版字段。
- 条目顺序、`display_index`、`position`、`depth`、`enabled` 必须由装配 QA 校验。

### 3.2 触发硬规则

正式触发型业务条目统一：

- `keys = [单一正则]`
- `secondary_keys = []`
- `use_regex = true`
- `prevent_recursion = true`
- `exclude_recursion = true`

角色本体与角色能力：只扫描 `<story_scene>`。

地点：只扫描 `<status>` 中的 `当前位置:`。

禁止把关键词数组直接做成普通逗号列表；禁止角色/能力正则扫整段 status；禁止地点正则扫整篇剧情正文。

### 3.3 蓝灯与绿灯

- 蓝灯：常驻核心规则，正文必须瘦身，只保不可变底层事实。
- 绿灯：关键词/regex 触发，按需展开。
- 绿灯不得依赖自身正文触发下一条绿灯形成递归链。
- 蓝灯不得因绿灯扩展而复制重复正文。

### 3.4 时间线

- 每卷/阶段时间线为完整 `<world_timeline>` 条目。
- 正文不混入 Markdown 标题、工程注释、迁移说明。
- 时间线不得全部同时常驻。
- 默认只启用开局所需时间线，其余保持 disabled；切换由后续正式运行层按成熟机制处理。
- 事件编号继续使用 A / A1 / A2 / B / C 语义，不在装配时重写剧情事件编号。

## 4. 内生世界正文净化

正式 Character Book 的 `content` 只能包含世界内事实。

不得进入运行时正文的内容包括但不限于：

- 母卡 / 原卡 / 授权 / 迁移 / AU 对照说明
- 施工单、QA、职责、封版、build、runtime 等工程说明
- `# BLUE` / `# GREEN` / 灯色 / 上位蓝灯等工程头
- 对“高中版→大学版”“原作→派生版”的制作层解释

大学世界线、替身存在、人物身份与关系必须直接作为世界事实陈述。

## 5. MVU 边界

本轮先装业务世界书，不提前把 MVU 系统条目混入业务 Character Book。

后续轻量 MVU 施工时，`initvar / update / output / list` 四条按全栈空模板原样接入：

- initvar 保持 disabled，由 MVU 读取；
- MVU 不成为第二剧情真相源；
- 不在业务世界书里自造另一套状态容器、变量 API 或生命周期。

## 6. 历史坑拦截清单

以下问题任一出现，本轮世界书不得标记 PASS：

1. 蓝灯与绿灯职责混装或绿灯被常驻。
2. 角色本体与替身能力重新合并为一个条目。
3. 触发关键词使用普通逗号列表而非单一 regex。
4. 角色/能力未限制在 `<story_scene>`；地点未限制在 `<status>` 的当前位置。
5. camelCase / snake_case 同义字段并存。
6. `prevent_recursion` / `exclude_recursion` 状态与全栈规范不符。
7. 工程说明、施工头、QA 文本进入运行时 `content`。
8. 多季时间线同时 enabled 导致上下文膨胀。
9. 时间线被拆成碎片或丢失 `<world_timeline>` 完整块。
10. 已封版的高阶替身形态被装配器提前解锁。
11. 旧高中世界线、未成年身份或旧反替身规则回灌。
12. 世界书与 MVU 各维护一套剧情/状态真相源。
13. 装配时擅自生成新角色、能力、地点或剧情事实。
14. 未经 QA 即把构建产物称为正式版或实机 PASS。
