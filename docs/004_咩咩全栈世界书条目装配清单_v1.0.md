# 004 咩咩全栈世界书条目装配清单 v1.0

## 0. 用途

本清单用于《辉夜大小姐想让我告白｜秀知院大学 × 替身》正式 Character Book 总装配。

唯一业务资料冻结点：`1f9ae635c82ff7cbaa08513b238429fa1663ee31`。

技术口径：咩咩制卡·全栈 v1.0.0 / chara_card_v3 / character_book。

任何条目类别缺失、数量不符、分区错误、递归配置错误或正文来源漂移，均不得标记世界书装配 PASS。

## 3. 记忆基础设施

必须存在：

1. `🗑️清空局部变量(别关)`
2. `【记忆相关:起始】`
3. `日常记忆存储`
4. `重大记忆存储`
5. `玩家身世背景`
6. `【记忆相关:结尾】`

其中：

- 清空局部变量：enabled=true；before_char；constant=true；selective=false。
- 三个记忆存储占位：enabled=false。
- 起止标记：空 content，只负责分区。

清空正文：

```text
{{setvar::combat_driver::}}
{{setvar::status_format::}}
{{setvar::世界书重大记忆存储::}}
{{setvar::世界书日常记忆存储::}}
{{setvar::世界书玩家身世背景::}}
```

三条记忆占位正文继承原卡已有 `setvar` 内容，不擅自开启。

## 4. 输出规则 / 时间线

必须存在：

- `【输出规则:起始】`
- `状态栏:默认`
- `战斗思维链`
- 9条完整时间线
- `【输出规则:结尾】`

### 4.1 状态栏:默认

来源：`worldbook/output-rules/original_output_rules.md`。

保留原卡 `status_format` 运行骨架，只做当前世界线必要的最小大学化：

- “秀知院学生”示例改为“秀知院大学学生”。
- “秀知院学园”位置示例改为“秀知院大学”。
- “桌游部”改为“桌游研究会”。
- 当前目标、身体、金钱、住所、当前位置、服装、行囊、玩家能力等字段继续保留。
- 不因为替身存在而删除普通生活/生存状态字段。

### 4.2 战斗思维链

来源：`worldbook/output-rules/original_output_rules.md`。

原卡规则继续承担：

- 考试 / 知识测验
- 体育竞技
- 社团或研究会专业技能比拼
- 其他明确基于知识/体育/熟练度的普通数值对抗

必须增加适用范围锁：

- **替身战不使用该知识/体育 Total_Score 公式。**
- 替身战按9蓝灯、34绿灯、对应角色能力条目与既有能力边界处理。
- 不得因为 `combat_driver` 存在，把 Crazy Diamond、D4C、King Crimson 等替身能力折算成知识/体育分数。
- 普通考试/体育比拼也不得因角色拥有强替身而自动获得分数优势。

其余原卡“专业部长不能被普通高属性无视”等现实能力差异原则保留。

### 4.3 时间线

三季正式时间线结构：

- 第一季：4条
- 第二季：4条
- 第三季：1条

合计：9条。

规则：

- 每条只保留完整 `<world_timeline>...</world_timeline>`。
- 不拆事件 A/A1/A2/B/C。
- `position=at_depth`，`extensions.position=4`，`depth=0`。
- 开局只启用开局时间线，其余 disabled。
- 不把三季9条全部常驻启用。
- 不因装配重新命名原事件标题或改日期。

MVU四条系统条目在最终整卡阶段按全栈空模板接入，不在 schema 未确定时猜内容。

## 5. 核心规则：9条蓝灯

位置：`【核心规则:起始】` 与 `【核心规则:结尾】` 之间。

数量：9。

统一字段：

```text
constant=true
selective=false
keys=[]
secondary_keys=[]
position=after_char
probability=100
prevent_recursion=false
exclude_recursion=false
```

蓝灯无关键词触发，不使用绿灯双防递归。

运行时正文只保留世界内 XML / 世界事实，删除 `# 蓝灯XX` 等工程标题。

---

## 6. 核心设定：34条绿灯 + 30条替身能力

位置：`【核心设定:起始】` 与 `【核心设定:结尾】` 之间。

### 6.1 34条绿灯

数量必须为34。

统一触发配置：

```text
constant=false
selective=true
keys=[单一正则]
secondary_keys=[]
use_regex=true
position=after_char
prevent_recursion=true
exclude_recursion=true
```

绿灯必须同时开启两个防递归。

绿灯关键词按实际语义设计，不能为凑触发率塞入高频普通词；正则必须保证不依赖其他绿灯已注入正文才能命中。

### 6.2 30条替身能力

每名替身使者一条独立能力条目，共30条。

能力条目：

- 与角色本体分离。
- 只扫描 `<story_scene>`。
- keys 为一个角色名/自然别称/替身专名组合成的单一 regex。
- `prevent_recursion=true`。
- `exclude_recursion=true`。
- 正文保留对应 `<角色名ability>` 或正式能力 XML，不把工程标题写进 content。
- 不提前解锁败者食尘、Go Beyond、GER、Tusk ACT2~4、Heavy Weather、C-MOON、Made in Heaven、Love Train、Star Platinum: The World 等后期能力。

## 7. 角色：44条

最终具名角色总数固定为44：

- 30名替身使者。
- 14名非替身使者。

装配算法必须为：

1. 从正式大学世界线人物源建立完整角色集合；
2. 以 `stand-augmented/` 对对应30名替身使者做覆盖；
3. 14名非替身角色继续使用大学世界线原正文；
4. 白银父与7名原创角色按已封版正式源加入；
5. 最终去重后必须恰好44名。

角色本体触发配置：

```text
constant=false
selective=true
keys=[/<story_scene>[\s\S]*?(?:本名|姓|名|昵称|常用别称)[\s\S]*?<\/story_scene>/s]
secondary_keys=[]
use_regex=true
position=after_char
prevent_recursion=true
exclude_recursion=true
```

禁止：

- 只装30名替身使者而漏14名普通角色；
- 同一角色大学版与增强版同时存在；
- 用替身专名触发人物本体却遗漏人物名字；
- 用单字姓氏/高频词造成全局误触发。

主要角色 / 其他角色的具体分区继承现有角色重要度与母版结构，不因是否拥有替身而机械划分。

## 8. 地点：11条

实际地点总数固定为11。

正式源：`locations/university_locations.md`。

触发：

```text
/<status>[\s\S]*?当前位置:[^\n<]*(?:地点正式名|简称|别称)[\s\S]*?<\/status>/s
```

统一：

```text
constant=false
selective=true
secondary_keys=[]
use_regex=true
prevent_recursion=true
exclude_recursion=true
```

地点正文转换为全栈 `<地点:名称>` 格式，并保留 `介绍:` 入口。

禁止旧高中措辞、旧母卡地点或剧情必然触发说明回灌。
