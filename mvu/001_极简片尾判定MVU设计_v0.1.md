# 001 极简片尾判定 MVU 设计 v0.1

## 0. 定位

本项目 MVU 不做大型仪表盘，不承担剧情推进，不重复世界书、状态栏或替身规则。

唯一业务目的：

> 在每次真正形成明确胜负/社死结算时，以《辉夜大小姐》式片尾判定口吻记录最新一句“今日……是某某的败北”，并提供单曲主题曲播放器。

整体原则：

- 极简；
- 有作品味道；
- 只记录最新结算，不做历史账本；
- 不成为第二剧情真相源；
- 不复制咩咩预设已有状态；
- 不修改咩咩预设；
- 底层继续使用咩咩制卡·全栈 v1.0.0 原生 MVU 九件套。

---

## 1. UI 结构

MVU 只有一张卡片，无分页、无 Tab、无地图、无人物列表、无好感面板。

### 1.1 上半区｜片尾判定牌

视觉结构：

```text
┌──────────────────────────────┐
│          本 日 の 勝 敗       │
│                              │
│    今日，是四宫辉夜的败北。   │
│                         敗北  │
├──────────────────────────────┤
│   ▶  混音主题曲   ━━━━━━━     │
└──────────────────────────────┘
```

设计语言：

- 米白/象牙白纸张底色；
- 黑色细边框；
- 深红色作为唯一强调色；
- 标题小字 `本日の勝敗`；
- 中文判定句为视觉中心；
- 可在右下角使用小型红色“敗北”印章感装饰；
- 不使用大面积动态背景；
- 不使用角色头像轮播；
- 不做复杂装饰，保持动画片尾字幕卡的干净感。

移动端优先：

- 单列布局；
- 不依赖 hover；
- 点击区 >= 44px；
- Android / SillyTavern 宽屏和窄屏均不横向溢出。

### 1.2 下半区｜单曲播放器

只播放一首“用户已混音确认的主题曲”。

播放器只保留：

- 播放 / 暂停；
- 当前进度；
- 曲名显示；
- 可拖动进度条。

不做：

- 歌单；
- 上一首 / 下一首；
- 随机播放；
- MVU内网易云搜索；
- 音乐好感或其他业务联动。

播放器使用全局唯一单例 `<audio>`，不得每条历史消息各创建一个音频实例。

消息重绘、MVU重新渲染时不得重复播放或同时叠音。

主题曲准确文件名当前尚未进入仓库，因此先冻结接口，不猜歌名：

- 预留仓库目录：`mvu/media/`
- 预留 manifest：`mvu/media-manifest.v1.json`
- 正式音频路径在用户上传已混音成品后登记。

## 2. MVU 业务 Schema

业务持久变量只保留一个：

```yaml
today_verdict: "今日，胜负未定。"
```

不新增：

- 胜者数组；
- 败者数组；
- 胜负次数；
- 连胜；
- 历史战绩；
- 日期计数器；
- 好感度；
- 替身数值；
- 世界线进度镜像；
- 音乐播放状态。

原因：这些都不是本 MVU 的必要真相源。

音乐的播放 / 暂停 / currentTime 属于 UI 临时状态，由前端维护，不进入模型变量。

## 3. today_verdict 更新规则

### 3.1 何时更新

仅当当前剧情中出现一个已经完成、具有明确结算感的事件时更新，例如：

- 恋爱头脑战明确分出输家；
- 赌局 / 游戏 / 比赛明确结算；
- 某人的计划明确失败；
- 某人因能力使用、误会或嘴硬造成典型社死；
- 一次替身小冲突形成明确的喜剧性/剧情性败北；
- 双方同时把事情搞砸，形成双败；
- 明确没有任何一方取得目的，形成无胜者。

### 3.2 何时不更新

以下情况 JSONPatch 保持空数组：

- 普通聊天；
- 场景尚在进行；
- 只有情绪变化但没有结算；
- 替身战尚未结束；
- 只是出现一次攻击或技能成功；
- 无法判断谁真正输掉本次“目的层”对决；
- 为了每回合都显示新句子而强行判输赢。

即：旧结算可以连续保留多轮，直到出现新的真正结算。

### 3.3 文案格式

默认：

`今日，胜负未定。`

单人败北：

`今日，是四宫辉夜的败北。`

多人共同败北：

`今日，是四宫辉夜与白银御行的双败。`

无胜者：

`今日，无胜者。`

允许根据人物关系做极轻微措辞变化，但必须保持短句、片尾字幕感；禁止展开成长段落、原因分析或战报。

### 3.4 “胜负”判断原则

胜负判断以“人物本轮实际目的是否达成”为优先，而不是单纯看：

- 谁打赢了替身战；
- 谁数值高；
- 谁说服了对方；
- 谁先离开现场。

例如：

- 能力发动成功，但告白诱导彻底失败 → 可以判能力使用者败北；
- 双方都成功隐藏心意，但都没得到想要的推进 → 可以判双败；
- 一方嘴硬成功保住面子，却把关系搞得更糟 → 仍可判其败北。

这与本项目“能力成功、恋爱目的失败”的喜剧基调一致。

## 4. 全栈接线

继续复用咩咩制卡·全栈 v1.0.0 原生 MVU 九件套：

角色脚本：

1. `MVU`
2. `MVU ZOD`
3. 本项目独立轻量 UI Bridge

世界书四条：

1. `[initvar]变量初始化勿开`
2. `[mvu_update]变量更新规则`
3. `[mvu_update]变量输出格式`
4. `变量列表`

局部正则继续使用全栈原生变量状态栏 / `<StatusPlaceHolderImpl/>` 接口，不自造第二套 MagVarUpdate、registrar 或变量容器。

`[initvar]变量初始化勿开` 必须保持 disabled。

MVU 四条系统条目按全栈模板使用双防递归：

- `prevent_recursion=true`
- `exclude_recursion=true`

业务世界书已有 157 条不因 MVU 设计反向重排；接入四条系统世界书后总数预期为 161。

## 5. UI Bridge 职责

独立 UI Bridge 只负责：

- 读取最新有效 MVU `today_verdict`；
- 渲染片尾判定牌；
- 维护唯一播放器 DOM；
- 读取 `mvu/media-manifest.v1.json` 的唯一主题曲；
- 保证热重载 / 消息重绘不重复挂载；
- Android 点击与拖动进度条；
- 音频加载失败时静默降级为“主题曲未就绪”，不阻断 MVU 判定牌。

UI Bridge 禁止：

- 推进剧情；
- 修改 worldbook enabled；
- 自动给人物判定新的替身能力；
- 写入好感；
- 改写时间线；
- 从 UI 点击直接写 `today_verdict`。

`today_verdict` 只由模型通过原生 MVU JSONPatch 在剧情真正结算时更新。

---

## 6. 音乐生命周期

- 全卡只存在一个主题曲 audio 实例；
- 用户主动点击播放后才播放，不强制绕过浏览器自动播放限制；
- MVU重绘不重置播放位置；
- 切换历史消息不创建第二音轨；
- 暂停后保留 currentTime；
- 音频结束后停在结尾，默认不自动循环；
- 后续若用户明确要求循环，再单独开启，不预设。

## 8. 当前设计结论

本 MVU 的核心不是“管理系统”，而是一张会随剧情留下最后一句话的片尾判定牌。

世界书负责世界与剧情事实；咩咩状态栏负责玩家当前状态；MVU只负责：

> **今天，谁输了。**

以及：

> **把那首已经混好的主题曲放出来。**
