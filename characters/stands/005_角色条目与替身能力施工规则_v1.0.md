# 角色条目与替身能力施工规则 v1.0

## 1. 施工目标

本阶段只在既有咩咩角色结构上追加替身信息，不重写成熟人物正文，不修改原卡母版。

人物主体继续严格保持：

`<角色名character> ... </角色名character>`

心理模型、Trauma / Defense / Trigger / Need、对话范例、外貌、关系与既有性格原则上原样保留。

## 2. 人物条目固定新增字段

每个已冻结替身的正式人物条目只新增两条，统一放在外观字段结束、`心理模型:` 之前：

```text
替身: <正式替身名>
替身觉醒契机: <过去发生过的一句简短事实>
```

规则：
- `替身`只写当前权威状态已经冻结的正式分配。
- `替身觉醒契机`只写过去事件，不写未来剧情，不展开长篇背景。
- 觉醒必须同时符合“角色本身具有替身资质/潜质 + 现实事件触发”，不得写成单纯情绪数值达到阈值就自动觉醒。
- 觉醒事件只解释“为什么在那时显现”，不得反过来修改人物原作经历与心理模型。
- 不把JOJO原使用者的人格、经历、阵营、道德与关系继承给《辉夜大小姐想让我告白》角色。

## 3. 替身能力条目

角色能力单独维护，不把完整能力说明塞回人物正文。

能力条目统一包含：

```text
<角色名ability>
角色: ...
替身: ...
JOJO原作机制:
- ...
本项目边界:
- ...
专属梗:
- ...
</角色名ability>
```

### JOJO原作机制
- 忠实采用对应漫画正传替身的既有能力、限制、媒介、射程逻辑与特殊机制。
- 不为了适配角色新增原创基础能力。
- 同名不同世界替身必须注明具体版本，例如JoJolion版Killer Queen。
- 原作存在附属能力时按原套装处理，例如King Crimson的Epitaph、JoJolion Killer Queen的Sheer Heart Attack。

### 本项目边界
- 特殊进化、Requiem、ACT、高阶形态、时间停止等若已明确不是开局能力，必须单独写明未觉醒/后续可能。
- 情感只作为替身输出与发挥的驱动力，不生成原作不存在的新能力。
- 既有世界规则优先：真实情感可以放大既有表现，但不能越过替身原本机制。

### 专属梗
- 可以保留JOJO社区常见梗、原作名场面梗、替身自身反差梗，以及与当前角色自然产生的二次笑点。
- 梗只能作为表现层，不改变能力判定。
- 例如：Hermit Purple可保留“最没用的替身”梗；Mandom可保留“现实SL只有6秒”；Crazy Diamond可保留“能修别人，修不了自己”。

## 4. 触发与装配

- 人物继续保持原卡绿灯触发结构。
- 替身能力条目后续使用角色名、自然简称与替身名共同触发。
- 当前角色生产阶段只维护可读源文件；最终ID、order、regex、recursion等运行元数据在角色层全部完成后统一装配，避免现在污染原83条基线与尚未修复的final assembler。

## 5. 批次

- Batch01：学生会核心六人，用于校准角色新增字段与能力条目格式。
- Batch01通过后，后续按已冻结替身分配批量推进。
